# Структура и медиафайлы

## Карта папок

```text
my-site/
├─ src/
│  ├─ .vitepress/
│  │  ├─ config.ts        # конфиг VitePress и темы
│  │  └─ theme/           # подключение темы и свои стили
│  ├─ site.yaml           # настройки, общие для всех локалей
│  ├─ ru/                 # локаль — папка называется как язык
│  │  ├─ _site.yaml       # настройки локали: заголовок, nav, sidebar, footer
│  │  ├─ index.md         # лендинг локали (layout: landing)
│  │  ├─ doc/             # документация (layout: doc)
│  │  └─ page/            # отдельные страницы
│  ├─ public/             # статические файлы
│  └─ index.md            # корень сайта: страница выбора языка
└─ package.json
```

## Папки локалей обязательны

Весь контент лежит внутри папки локали: `src/ru/`, `src/en/`, `src/pt-BR/`.
Правило действует и для одноязычного сайта — одна папка локали совершенно
нормальна. В корне `src/` допускается единственный markdown-файл —
`index.md`, страница выбора языка.

`defineLandingConfig` проверяет это при сборке: локаль `root` или markdown-файл
в корне `src/` (кроме `index.md`) останавливают сборку с подсказкой, куда
перенести файл. Папка считается локалью, если содержит `_site.yaml` или
`_site.ts`.

## Вложенные папки в doc/ и page/

`doc/` и `page/` — не плоские списки. Внутри можно строить любую структуру,
URL повторяет расположение файлов:

```text
src/ru/
├─ doc/
│  ├─ index.md                    → /ru/doc/
│  ├─ blocks.md                   → /ru/doc/blocks
│  └─ guide/
│     ├─ install.md               → /ru/doc/guide/install
│     └─ advanced/
│        ├─ index.md              → /ru/doc/guide/advanced/
│        └─ media/scheme.svg
└─ page/
   ├─ links.md                    → /ru/page/links
   └─ pricing/
      ├─ index.md                 → /ru/page/pricing/
      └─ media/hero.svg
```

`index.md` внутри папки даёт папочный URL: `doc/guide/advanced/index.md`
открывается как `/ru/doc/guide/advanced/`, а не `…/index`.

Боковое меню документации тема **не** собирает из файловой системы — оно
задаётся вручную в `themeConfig.sidebar` внутри `_site.yaml`. Ссылки в нём
указываются относительно локали, поэтому вложенный файл добавляется так:

```yaml
themeConfig:
  sidebar:
    doc:
      - text: 'Руководство'
        items:
          - text: 'Установка'
            link: 'guide/install'
          - text: 'Продвинутое'
            link: 'guide/advanced/'
```

## Где хранить изображения

Есть три способа, и их можно смешивать.

### 1. Общая папка public

```text
src/public/img/hero.svg
```

```yaml
blocks:
  - type: hero
    image: /img/hero.svg
```

Подходит для логотипов, скриншотов продукта, OG-изображений — всего, что
используется на нескольких страницах.

### 2. Рядом с markdown-файлом

```text
src/ru/page/pricing.md
src/ru/page/table.svg
```

```md
![Тарифы](./table.svg)
```

### 3. Папка на страницу с подпапкой media

```text
src/ru/page/pricing/
├─ index.md
└─ media/
   ├─ hero.svg
   └─ table.svg
```

```yaml
---
layout: landing
blocks:
  - type: hero
    title: Тарифы
    image: ./media/hero.svg
---
```

```md
<!-- в теле markdown-страницы -->
![Таблица](./media/table.svg)
```

Всю страницу вместе с картинками можно перенести или удалить одной папкой.

## Относительные пути в блоках

В данных блоков относительным считается путь, начинающийся с `./` или `../`
— именно такие значения тема разворачивает в путь от корня сайта
(`./media/hero.svg` → `/ru/page/pricing/media/hero.svg`).

```yaml
blocks:
  - type: hero
    image: ./media/hero.svg      # ✅ относительно index.md страницы
    icon: fa6-solid:bolt         # имя иконки — не трогается
    bg: brand                    # вариант оформления — не трогается
  - type: features
    items:
      - image: /img/shared.svg   # путь от корня сайта — не трогается
```

Путь без `./` (например `media/hero.svg`) в блоках относительным **не**
считается — так имена иконок и служебные значения гарантированно остаются
нетронутыми. Всегда пишите `./`.

Разворачивание работает на любой глубине данных блока — в массивах `items`,
`actions`, во вложенных объектах.

## Как это работает при сборке

- **Изображения в теле markdown** обрабатывает Vite: файл получает хеш в
  имени, мелкие встраиваются как data-URI.
- **Все медиафайлы из дерева контента** копируются в сборку с сохранением
  пути, поэтому относительная ссылка в собранном сайте работает так же, как
  в `dev`.
- **Пути в блоках и во фронтматере** тема разворачивает в путь от корня
  сайта — эти значения попадают ещё и в `og:image` и JSON-LD, где
  относительный путь был бы некорректен.

Копируются обычные медиа-расширения: изображения (`png`, `jpg`, `jpeg`,
`gif`, `svg`, `webp`, `avif`, `ico`, `bmp`), видео (`mp4`, `webm`, `ogv`,
`mov`, `m4v`), аудио (`mp3`, `wav`, `ogg`, `oga`, `m4a`, `flac`, `aac`) и
`pdf`. Папка `public/` и папки, начинающиеся с точки, не затрагиваются.

::: tip Хеширование и кеш
У файлов рядом со страницей в имени нет хеша — как и у файлов из `public/`.
Заменив картинку под тем же именем, добавьте версию в имя файла
(`hero-v2.svg`), чтобы не полагаться на кеш браузера.
:::
