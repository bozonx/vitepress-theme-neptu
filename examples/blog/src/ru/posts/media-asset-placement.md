Тема поддерживает три способа организации изображений и других медиафайлов.
Все три работают и для обложек (frontmatter `cover`), и для изображений в
тексте (markdown `![alt](src)`), и для медиа-компонентов. Выберите тот,
который подходит вашему рабочему процессу — их можно свободно смешивать.

## 1. Общая папка public

Классический подход VitePress. Все медиа лежат в `src/public/` и
указываются абсолютным путём от корня public.

```text
src/
├─ public/
│  └─ img/
│     ├─ cover.jpg
│     └─ screenshot.png
└─ ru/
   └─ posts/
      └─ my-article.md
```

```yaml
# frontmatter
cover: /img/cover.jpg
```

```md
<!-- тело статьи -->
![Скриншот](/img/screenshot.png)
```

**Когда использовать**: небольшие блоги с малым количеством изображений,
общие ассеты для нескольких постов, общие ассеты для разных языковых версий постов (например общая обложка для всех переводов поста) или когда просто удобнее держать всю медиа в одной папке.

## 2. Рядом с markdown-файлом

Изображения лежат рядом с `.md`-файлом и указываются относительным путём.

```text
src/
└─ ru/
   └─ posts/
      ├─ my-article.md
      ├─ my-other-article.md
      ├─ cover.jpg
      └─ screenshot.png
```

```yaml
# frontmatter — относительный путь
cover: ./cover.jpg
```

```md
<!-- тело статьи — относительный путь -->
![Скриншот](./screenshot.png)
```

**Когда использовать**: когда медиа файлов не много и они не сильно засоряют папку с постами.
Так же удобен вариант кастомной структуры папок в `posts/` где можно сгруппировать несколько постов в отдельную папку и положить рядом с ними их картинки и другие медиа файлы.

## 3. Папка на статью с подпапкой media

Каждая статья получает свою директорию. Markdown-файл называется `index.md`,
а медиа лежат в подпапке (обычно `media`). URL остаётся чистым:
`/ru/posts/my-article/`.

```text
src/
└─ ru/
   └─ posts/
      └─ my-article/
         ├─ index.md
         └─ media/
            ├─ cover.jpg
            ├─ diagram.svg
            └─ photo.png
```

```yaml
# frontmatter — относительно index.md
cover: ./media/cover.jpg
```

```md
<!-- тело статьи — относительно index.md -->
![Диаграмма](./media/diagram.svg)
![Фото](./media/photo.png)
```

**Когда использовать**: статьи с большим количеством изображений, лонгриды
со множеством скриншотов, когда хочется переносить статью (текст + медиа)
одной папкой.

## Особенности работы медиа путей

- Все 3 подхода можно совмещать в одном блоге
- При любом подходе, даже при статья с подпапкой media можно делать вложенную структуру - подстатьи
- Все три подхода получают автоматические `width`/`height` и для обложек, и
для отдельных изображений в тексте (тех, что оборачиваются в `<figure>`).
- Встроенные компоненты темы (`YoutubeVideo`, `VideoFile`, `AudioFile`, `FileDownload`) работают со всеми тремя подходами. поле url укаызваете по такому же принципу: `<VideoFile url="/media/demo.mp4" />` или например `<VideoFile url="./media/demo.mp4" />`
- Обрабатываются файлы обычных медиа-расширений: изображения (`png`, `jpg`, `jpeg`,
`gif`, `svg`, `webp`, `avif`, `ico`, `bmp`), видео (`mp4`, `webm`, `ogv`,
`mov`, `m4v`), аудио (`mp3`, `wav`, `ogg`, `oga`, `m4a`, `flac`, `aac`) и
`pdf`. Папка `public/` и служебные папки, начинающиеся с точки, не
затрагиваются.

::: tip Хеширование и кеш
У файлов рядом со статьёй в имени нет хеша — как и у файлов из `public/`.
Если вы заменили картинку, оставив то же имя, посетителю может понадобиться
обновить страницу. Для часто меняющихся изображений добавляйте версию в имя
файла: `diagram-v2.svg`.
:::
