Как только на сайте появляется реклама или счётчик посещений, хранящий куки,
появляется и вопрос согласия. Тема закрывает ту часть, которую сторонний сервис
за вас сделать не может, но **баннер согласия тема не рисует**.

::: warning Это не юридическая консультация
Ниже — техническая сторона вопроса и требования площадок. Формулировки политики,
состав категорий и применимость к вашей аудитории — на вашей стороне.
:::

## Нужен ли баннер

Коротко: если вы показываете рекламу или собираете аналитику, используя куки файлы и среди читателей есть жители ЕЭЗ или Великобритании — да. Аналитика без куки
(Plausible, Umami, GoatCounter) согласия не требует.

- **ePrivacy Directive** требует получить согласие **до** записи и чтения
  некритичных куки и аналогичных хранилищ. Реклама и аналитика на куки сюда
  попадают; cookieless-счётчики — нет.
- **GDPR** добавляет требования к самому согласию: оно должно быть
  предварительным, информированным, добровольным и **отзываемым**, а отказаться
  должно быть не сложнее, чем согласиться.

## Как включить баннер

Тема Neptu blog не имеет своего баннера согласия, так как он просто не может
удовлетворять жёстким требованиям регуляторов. Баннер нужно подключить отдельно:

- **Реклама Google (AdSense / Ad Manager)** с читателями из ЕЭЗ/Великобритании —
  Google требует TCF-сертифицированную CMP. Проще всего включить
  **Privacy & messaging** в интерфейсе AdSense.
- **Только аналитика на куки, без рекламы Google** — сертификация не нужна,
  подойдёт любой опенсорсный баннер или свой собственный. Связать его с темой
  поможет `useConsent()` (ниже). Для аналитики без использования куки файлов баннер не нужен.

| Вариант | Кому | Замечание |
| --- | --- | --- |
| **Privacy & messaging в интерфейсе AdSense** | тем, у кого AdSense | Бесплатно, сертифицирована, кода писать не нужно вообще — включается галочкой в аккаунте. |
| Cookiebot, Usercentrics, CookieYes | нужен свой дизайн и категории | Freemium, сертифицированы |
| Klaro, vanilla-cookieconsent | только аналитика, без рекламы Google | Опенсорс, **не** сертифицированы TCF |

## Что делает тема

Тема даёт **слой согласия** — то, что CMP не может сделать за неё, потому что
это должно произойти до её загрузки.

### Consent Mode v2 в `<head>`

Тема вставляет первым скриптом на странице значения по умолчанию для четырёх
сигналов Google Consent Mode v2:

| Сигнал | Что закрывает |
| --- | --- |
| `analytics_storage` | Аналитика |
| `ad_storage` | Рекламные куки |
| `ad_user_data` | Передача пользовательских данных в Google |
| `ad_personalization` | Персонализация рекламы |

Все — в `denied`. Порядок здесь принципиален: сигналы действуют только на теги,
которые загрузились **после** них, поэтому скрипт стоит раньше gtag.js, AdSense
и самой CMP. Иначе первый хит уйдёт мимо запрета.

Тот же скрипт восстанавливает решение вернувшегося читателя, чтобы он не
считался «отказавшимся», пока CMP просыпается.

```ts
// .vitepress/config.ts — значения по умолчанию, менять обычно не нужно
export default async () => defineBlogConfig({
  themeConfig: {
    consent: {
      enabled: true,
      waitForUpdate: 500, // сколько теги ждут ответа CMP, мс
      // region: ['ES', 'US-CA'], // ограничить регионами (ISO 3166-2)
      // defaults: { analytics: true }, // если вам это подходит юридически
    },
  },
})
```

`consent.enabled: false` отключает скрипт — это нужно, только если CMP
выставляет значения по умолчанию сама. Держать оба источника не стоит:
выигрывает тот, кто вызвался последним, и это не всегда тот, на кого вы
рассчитывали.

### `useConsent()`

Composable — шов, в который включается CMP. Вызовите его из колбэка CMP, и тема
сохранит решение, отправит `gtag('consent', 'update', ...)` и перерисует
рекламные блоки, если они ждут согласия.

```ts
import { useConsent } from 'vitepress-theme-neptu/composables'

const { consent, hasDecided, adsAllowed, set, acceptAll, rejectAll, reset } =
  useConsent()

// из колбэка вашей CMP
set({ analytics: true, ads: false, adUserData: false, adPersonalization: false })

// ссылка «изменить настройки куки» в футере
reset()
```

Решение живёт в `localStorage` (`consent.storageKey`, по умолчанию
`neptu-consent`) и синхронизируется между вкладками.

Если ваша CMP управляет Consent Mode самостоятельно, `useConsent()` можно не
трогать вовсе — тема читает состояние только тогда, когда включён
`ads.requireConsent`.

## Реклама и согласие

```ts
themeConfig: {
  ads: {
    component: 'AdUnit',
    requireConsent: false, // по умолчанию
  },
}
```

`requireConsent: false` не означает «показывать рекламу без согласия».
Сертифицированная CMP сама решает, что показать посетителю: при отказе Google
переключается на неперсонализированную рекламу, а не перестаёт показывать
что-либо. Если бы тема прятала блок целиком, эти показы тоже пропали бы.

Ставьте `requireConsent: true`, когда нужно, чтобы до явного согласия не
загружалось вообще ничего — например, если рекламная сеть не поддерживает
Consent Mode.

## Чек-лист

1. Только счётчик без куки → баннер не нужен.
2. Google Analytics → нужен баннер; проще всего взять опенсорсный и связать
   через `useConsent()`.
3. AdSense или Ad Manager с читателями из ЕЭЗ/Великобритании → включите
   **Privacy & messaging** в интерфейсе AdSense. Ничего писать не нужно.
4. Скрипт Consent Mode тема ставит сама — трогать `consent.enabled` нужно,
   только если CMP делает это за вас.
