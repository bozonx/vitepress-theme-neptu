Вы пишете посты — а страницы-списки тема строит сама. Разберём, какие списки
доступны и откуда берётся отдельная страница вроде «О блоге». Настройка главной
страницы вынесена в отдельную статью — [Домашняя страница](home-page).

## Автоматические списки

Из ваших постов тема генерирует семь типов списков. Все они доступны из сайдбара
этого демо:

| Список | Что показывает | Адрес |
| --- | --- | --- |
| **Свежие** | все посты по дате, новые сверху | [`recent/1`](../recent/1) |
| **Избранное** | посты с `featured: true` | [`featured/1`](../featured/1) |
| **Популярное** | посты по просмотрам (нужен GA4) | [`popular/1`](../popular/1) |
| **Архив** | по годам, затем по месяцам | [`archive/`](../archive/) |
| **Авторы** | посты каждого автора | [`authors/`](../authors/) |
| **Теги** | посты по каждому тегу | [`tags/`](../tags/) |
| **Категории** | посты по каждой рубрике | [`categories/`](../categories/) |

Создавать эти страницы вручную не нужно — они собираются на сборке. Какие из них
показывать в сайдбаре, решает `sidebar` (см. [Настройки themeConfig](themeconfig-settings)):

```yaml
# src/<локаль>/_site.yaml
themeConfig:
  sidebar:
    recent: true
    featured: true
    popular: true     # требует popularPosts.enabled в config.ts
    archive: true
    authors: true
    tags: true
    categories: true  # по умолчанию выключено
```

«Популярное» опирается на данные Google Analytics и работает, только когда задан
источник GA4 — подробности в [популярных постах через GA4](popular-posts).

Сколько постов помещается на страницу списка, задаёт `perPage` в
`.vitepress/config.ts` — это build-time параметр, в YAML он не работает (см.
[Уровни конфигурации](config-layers)). Сколько номеров страниц показывает
пагинация, задаёт `paginationMaxItems` (по умолчанию 5).

## Избранные посты

`featured: true` во frontmatter добавляет статью в редакционную подборку:

```yaml
---
title: Статья, с которой стоит начать
date: 2026-08-01
featured: true
---
```

Флаг ничего не меняет в порядке свежих постов, архива, лент и похожих
материалов — он только наполняет страницу [`featured/1`](../featured/1),
одноимённую секцию сайдбара и секцию `featured` на главной. Внутри подборки
посты идут от новых к старым.

## Авторы, теги и категории

- **Авторы** берутся из [`_authors.yaml`](../authors/): пост ссылается на автора
  через `authorId`, а тема строит страницу автора и подставляет его данные в футер
  и микроразметку.
- **Теги** берутся прямо из поля `tags` постов; отдельный реестр тегов вести не
  нужно.
- **Категории** берутся из поля `category` (или `categories`). Одна категория на
  пост задаёт раздел блога и хлебные крошки. Реестр им не нужен. Подробнее —
  [Категории и теги](categories-and-tags).

## Отдельные страницы

Не всё в блоге — статья. Для постоянных страниц (о блоге, контакты, правила)
создайте файл в `src/<локаль>/pages/` с `layout: page`:

```md
---
title: О блоге
layout: page
---

# О блоге

Обычный Markdown. Такая страница не попадёт в ленты, архив и списки —
это просто документ.
```

Ссылаться на неё удобно из навигации, футера или нижних ссылок сайдбара
(`href: 'pages/about'`). Живые примеры — [«О блоге»](../pages/about) и
[«Ссылки»](../pages/links).

## Карточки постов в списках

Карточки постов в списках (например, на страницах **Свежие посты**, **Теги** и
**Авторы**) отображают краткое превью. По умолчанию тема генерирует превью из
начала текста поста, но его можно переопределить.

### Три способа управления превью

**1. Автоматический (по умолчанию).** Ничего не делайте — тема сделает выжимку из текста статьи
длиной до `maxPreviewLength` символов.

**2. Использование описания.** Установите `descrAsPreview: true`, чтобы использовать поле `description`
из frontmatter как текст карточки (так сделано в большинстве демо-постов).

**3. Явный текст.** Задайте `previewText`, чтобы вручную написать текст карточки. Используйте
`descrAsPreview` **или** `previewText`, но не оба вместе.

```yaml
# Явный текст превью:
previewText: "Текст этой карточки задан явно через previewText…"

# Или альтернативный вариант:
# descrAsPreview: true
```

### Длина превью

Длину автоматического превью задавайте **только в `config.ts`**: текст обрезается
на этапе сборки в data-лоадере локали, а он читает именно этот экспорт:

```ts
// .vitepress/config.ts
export const postList = { maxPreviewLength: 300 }
```

Ключ `postList.maxPreviewLength` в YAML схема тоже примет, но на уже обрезанный
текст карточки он не повлияет — не дублируйте его там.

### Элементы карточки

Отображение элементов карточки (дата, теги, миниатюра, автор) настраивается в YAML:

```yaml
# src/site.yaml
themeConfig:
  postList:
    showDate: true
    showTags: true
    showThumbnail: true
    showPreview: true
    showAuthor: true
```
