Блог, который вы [скопировали из шаблона](getting-started), имеет стандартизированную
структуру. Разберём её, чтобы вы знали, какой файл открывать для каждой задачи.

## Структура вашего блога

```text
my-blog/
├─ src/
│  ├─ .vitepress/
│  │  ├─ config.ts        # конфиг 1го уровня, системные настройки
│  │  └─ theme/           # расширения темы и свои стили
│  ├─ ru/                 # локаль — папка называется как язык
│  │  ├─ posts/           # ваши посты
│  │  ├─ pages/           # отдельные страницы (О блоге, Донат…)
│  │  ├─ _authors.yaml    # профили авторов
│  │  ├─ _categories.yaml # рубрики этой локали
│  │  ├─ _site.yaml       # Конфиг 3го уровня для конкретной локали
│  │  └─ index.md         # главная страница локали
│  ├─ public/             # статические файлы (медиа, иконки, robots.txt)
│  ├─ site.yaml           # Конфиг 2го уровня. Общие настройки для всех локалей
```

Это основные файлы и папки с которыми вам предстоит работать, но так же вы можете увидеть и другие папки и файлы - это служебные файлы, которые не рекомендуется редактироваться без необходимости.

## Чем отличаются посты (posts/) от страниц (pages/)

- **Посты** это [ваш основной контент](first-post), который показывается в списках последних постов, популярных постов и тд, а так же в RSS, Atom и JSON фидах (если они настроены).  Каждый пост должен иметь дату, расценивайте ее как дату публикации. Списки постов 
формируются именно по этой дате. Посты располагаются в соответсвующей папке локали `src/<локаль>/posts/`.
- **Страницы**, в отличии от постов, не имеют даты публикации, не попадают в списки контента и в фиды, они предназначены для вывода различной информации, например: о блоге, об авторе, ссылки на соц сети или способы доната. Каждая страница должна иметь поле в frontmatter `layout: page`. Страницы располагаются в `src/<локаль>/pages/`.

## Папки локалей

Весь контент лежит внутри папки локали, которая представляет из себя языковой тег BCP 47: `src/ru/`, `src/en/`, `src/pt-BR/`, `src/zh-CN/`. Это правило действует и для одноязычного сайта - если вы делаете блог только на одном языке, то всеравно нужно использовать папку локали, например `src/ru/`.

Где брать коды и названия, разобрано в [Как назвать локаль](locales#как-назвать-локаль).

::: info
VitePress-локаль `root` темой не поддерживается. а в корне `src/` может находиться единственный markdown-файл — `index.md`, он рендерит страницу выбора языка.
:::

## Вложенные папки внутри posts/ и pages/

`posts/` и `pages/` — это, не обязательно плоская структура файлов. Внутри можно строить любую вложенную структуру, при этом URL повторяет расположение файлов. Например:

```text
src/ru/
├─ posts/
│  ├─ hello-world.md              → /ru/posts/hello-world
│  ├─ my-article/
│  │  ├─ index.md                 → /ru/posts/my-article/
│  │  └─ media/cover.jpg
│  └─ 2026/
│     └─ trip/
│        ├─ day-one.md            → /ru/posts/2026/trip/day-one
│        └─ day-one-photo.jpg
└─ pages/
   ├─ about.md                    → /ru/pages/about
   └─ pricing/
      ├─ index.md                 → /ru/pages/pricing/
      └─ media/table.svg
```

Два правила, о которых стоит помнить:

- **`index.md` даёт папочный URL.** `posts/my-article/index.md` открывается по
  адресу `/ru/posts/my-article/`, а не `/ru/posts/my-article/index`.
- **Подпапки не создают разделов.** Вложенность — это способ организовать файлы; группировкой контента для читателя занимаются теги, категории и архив по датам, а не путь.

## Настройте ваш блог

Файлы в `my-blog/src/` которые следует отредактировать чтобы настроить ваш блог:

- `.vitepress/`
  - `config.ts` — siteUrl, поиск, подключение внешних css и js файлов, интеграция с google analitics, использование переменных окружения. Это конфиг 1го уровня для разработчиков
  - `theme/`
    - `styles.css` — ваши корректировки стиля темы под ваш вкус а так же переопределение стандартных CSS-переменных
- `<локаль>/`
  - `_authors.yaml` — авторы этой локали или локализованные имена и другие данные авторов указанных в глобальном списке авторов в `src/site.yaml`
  - `_categories.yaml` — рубрики этой локали: `id`, по которому на них ссылаются посты, и название на языке локали
  - `_site.yaml` —  конфиг конкретной локали (3 уровня), а так же дополнения и переопределение отдельных параметров глобального конфига `src/site.yaml`
  - `index.md` — главная страница этой локали, можете добавить свой текст, он отобразится на главной странице под блоком `hero`
- `public/` — картинки, иконки, медиа, robots.txt и другие файлы которые будут скопированы в билд как есть, не проходя никакой обработки
- `site.yaml` — настройки для всех локалей сразу (конфиг 2 уровня для администраторов блога)

Три слоя конфигурации (`config.ts` → `site.yaml` → `_site.yaml`) устроены не
случайно — как они сочетаются и какой из них главнее, разбирается в разделе
[Уровни конфигурации](config-layers).

## Специальные файлы и папки

Все списки, такие как свежие, популярные, архив, авторы, теги, категории генерируются автоматически из ваших постов. Папки в вашей локали (например `src/ru/`) `archive/`, `authors/`, `categories/`, `featured/`, `popular/` содержат файлы которые уже настроены для формирования страниц с соответствующими списками, их редактировать не нужно.

Если вы не используете какую-то вышеперечисленную функциональность, то помимо выключения ее в настройках, так же удалите соотвествующие папки: `authors/`, `categories/`, `featured/`, `popular/`, чтобы они не билдились впустую и не увеличивали время билда.

Так же в папке локали находятся специальные файлы:
- `getAllPosts.ts` - служебный файл, его редактировать не нужно
- `loadPosts.data.ts` - так же служебный файл, его редактировать не нужно

А в самом корне src находится `index.md` который рендерит страницу выбора языка, этот файл так же не подлежит редактированию, но если хотите можете поменять его стиль, прописав свои стили в файле `.vitepress/theme/styles.css` для css класса `.locale-selector-wrapper` и его потомков.
