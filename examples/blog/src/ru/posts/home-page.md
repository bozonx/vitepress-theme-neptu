Главная страница локали `src/<локаль>/index.md` выглядит так:

```md
---
layout: home
---

Ваш текст который будет выведен после блока Hero.
```

В самом `index.md` файле можно указать любой контент, который будет выведен после блока Hero либо не писать ничего, остальные параметры задаются в конфиге в сексии `themeConfig.home`.

> Обратите внимание что речь идет именно о домашней странице локали `src/<локаль>/index.md`, а не о самой корневой странице `src/index.md`, которую редактировать не рекомендуется и которая используется для вывода корневой страницы где предлагается выбрать язык. Эта страница может показхаться бесполезной, но это разумный компромис, так как делать редирект с корня на домашнюю страницу локали с помощью JS скрипта не рекомендуется поисковиками такими как Google. Но при желании вы можете настроить там серверный редирект на вашем хостинге.

## Hero-блок

```yaml
# site.yaml
themeConfig:
  home:
    # auto | light | dark — режим темы на главной. Если установить light | dark то тему нельзя будет переключать на главной странице
    appearance: auto
    # максимальная ширина контента в пикселях
    maxWidth: 800
    background:
      # none | parallax — параллакс-фон при скролле
      type: none
      # путь к фоновому изображению (только с type: parallax)
      # image: /img/home.webp
      # смещение параллакс-фона в пикселях при скролле
      # parallaxOffset: 300
```

> Все пять параметров из этого блока можно перекрыть во frontmatter самого
> `index.md` — полями `homeTheme`, `homeMaxWidth`, `homeBackground`,
> `homeBackgroundImage` и `homeBackgroundParallaxOffset`. Это удобно, когда
> локалей несколько и одной из них нужен свой фон. Подробности — в статье
> [Все поля frontmatter](frontmatter#главная-страница-layout-home).

```yaml
# ru/_site.yaml
themeConfig:
  home:
    hero:
      # заголовок hero-блока
      title: 'Мой блог'
      # подзаголовок под заголовком
      description: 'Короткое описание блога'
      # Простой вариант одной картинки (рекомендуется 320×320px (или 640×640px для Retina), WebP/PNG/SVG):
      image: '/img/logo.webp'
      # Или с alt-текстом:
      # image: { src: '/img/logo.webp', alt: 'Логотип' }
      # Или разные картинки для светлой и тёмной темы:
      # image: { light: '/img/logo-light.webp', dark: '/img/logo-dark.webp', alt: 'Логотип' }
      # массив кнопок под hero-блоком
      actions:
        # Выделенная кнопка - primary
        - { text: 'Читать статьи', href: 'recent/1', primary: true }
        # Кнопка с иконкой
        - { text: 'Читать статьи', href: 'recent/1', icon: 'fa6-solid:bookmark' }
      sections:
        # массив секций под hero-блоком (см подродности ниже)
        - title: 'Последние статьи'
          description: 'Свежие материалы о разработке и технологиях'
          articles: 5
```

> **Требования к картинке в Hero:**
> - **Размеры:** рекомендуемый размер — **320×320px** (на мобильных устройствах масштабируется до 240×240px). Для Retina-экранов можно подготовить 640×640px.
> - **Формат:** лучший результат дают **WebP, PNG или SVG на прозрачном фоне** (маскоты, 3D-аватары, векторные логотипы). Тема автоматически накладывает мягкую объёмную тень (`drop-shadow`), адаптивную к тёмной и светлой теме.

## Секции

Порядок объектов в `sections` задаёт порядок блоков. Поддерживаются пять типов:

| Тип | Что выводит | По умолчанию |
| --- | --- | --- |
| `featured` | статьи с `featured: true` | включён |
| `latest` | последние статьи | выключен |
| `popular` | популярные по GA4 | выключен |
| `categories` | список категорий | включён |
| `tags` | облако тегов | включён |

```yaml
# site.yaml
themeConfig:
  home:
    sections:
      - { type: featured, enabled: true, limit: 3 }
      - { type: latest, enabled: false }
      - { type: popular, enabled: false }
      - { type: tags, enabled: true, limit: 15 }
      - { type: categories, enabled: true, limit: 10 }
```

`limit` ограничивает количество статей или тегов. Если его нет, показывается
одна страница — значение `themeConfig.perPage` из `.vitepress/config.ts`.
Пустая секция не рисуется: блок избранного на блоге без `featured`-постов
просто не появится.

Секция `popular` требует включённой интеграции с GA4 — по умолчанию она
выключена. Пока данных нет, список остаётся пустым, а сборка выводит
предупреждение. Как её включить — в статье [Аналитика и популярные посты](analytics).

## Лента постов вместо лендинга на главной

Главная с `layout: home` — это лендинг: hero, секции, опциональный
параллакс-фон и **никакого сайдбара**. Если вместо этого нужна обычная лента
постов, замените в `index.md` макет и вставьте тот же компонент, что использует
шаблон `recent/[page].md`:

```md
---
layout: util
---

<script setup>
import { RecentPostsList } from 'vitepress-theme-neptu/components'
</script>

<RecentPostsList :curPage="1" />
```

Для популярных постов подставьте `PopularPostsList` (нужен
`popularPosts.enabled`), для избранных — `FeaturedPostsList`.

Три отличия от страницы-шаблона:

- **`paths.js` не нужен.** `index.md` — статический маршрут, а не динамический
  `[page]`, поэтому `params.page` не задан и список открывает первую страницу.
- **Не копируйте `robots: noindex`.** Шаблоны списков помечают себя `noindex`,
  чтобы страницы пагинации не плодили дубли в выдаче. Главная, наоборот, должна
  индексироваться — блок `head` из шаблона не переносите.
- **Пагинация ведёт в никуда.** Базовый URL страниц считается от текущего
  маршрута, поэтому на `/ru/` ссылки укажут на `/ru/2`, которых не существует.
  Главная в этом режиме работает как первая страница ленты; полную пагинацию
  оставьте на `recent/1` и дайте на неё ссылку в навигации или сайдбаре.

Если и этого мало — соберите главную из отдельных компонентов или подключите
свой layout. Как это сделать — в [Кастомизации главной
страницы](customization#кастомизация-главной-страницы).
