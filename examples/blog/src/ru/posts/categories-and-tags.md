В теме две таксономии. Они устроены одинаково внутри, но решают разные задачи —
и потому задаются по-разному:

| | Категории | Теги |
| --- | --- | --- |
| Сколько на пост | обычно одна | сколько угодно |
| Смысл | раздел блога | свободные метки |
| Где описаны | `_categories.yaml` | нигде, прямо в посте |
| Хлебные крошки | строятся по ней | нет |
| Страницы | [`categories/`](../categories/) | [`tags/`](../tags/) |

Категорий у блога мало и они образуют его структуру — поэтому они перечисляются
один раз в реестре, а посты ссылаются на них по идентификатору. Тегов бывают
сотни, они возникают по ходу дела — их отдельно регистрировать не надо.

## Реестр категорий

Файл `src/<локаль>/_categories.yaml` — единственное место, где категории
описаны. Он устроен так же, как [`_authors.yaml`](authors). Если нужна логика
или вычисляемые значения, вместо YAML можно завести `_categories.ts` — модуль,
экспортирующий массив записей; `.ts` имеет приоритет, если оба файла существуют.

```yaml
# src/ru/_categories.yaml
- id: 'getting-started'
  name: 'Начало работы'

- id: 'configuration'
  name: 'Настройка'

- id: 'writing'
  name: 'Контент'
  slug: 'kontent'
```

У записи три поля, и различать их важно:

| Поле | Что это | Переводится |
| --- | --- | --- |
| `id` | ключ, по которому на категорию ссылаются посты | **нет**, одинаков во всех локалях |
| `name` | видимое название | да |
| `slug` | часть адреса | да, но по умолчанию равен `id` |

Обязателен только `id`. `name` и `slug` без явного значения берутся из него,
так что запись `- id: 'seo'` — уже рабочая категория с адресом
`/ru/categories/seo/1`.

::: tip Кастомные поля
В запись можно добавить любые дополнительные поля — например,
`description`. Тема их не выводит, но они проходят сквозь сборку и
доступны в `frontmatter.categories[]` для ваших собственных компонентов
или CMS.
:::

::: tip Можно и в `_site.yaml`
То же самое пишется в `themeConfig.categories` внутри `_site.yaml` — слои
объединяются по `id`. Но отдельный файл удобнее: его удбобно редактирвоать в CMS вроде Sveltia, и
он не раздувает конфиг сайта.
:::

::: tip Подсказки в редакторе
Добавьте в начало `_categories.yaml` строку
`# yaml-language-server: $schema=https://unpkg.com/vitepress-theme-neptu/schema/categories.schema.json`
— тогда редактор с yaml-language-server (VS Code, Neovim и др.) будет
подсказывать поля и проверять значения.
:::

## Как задать категорию посту

В посте указывается только `id` категории:

```yaml
---
title: Запуск блога за 5 минут
category: getting-started
tags:
  - guide
---
```

Если посту действительно нужно несколько рубрик то воспользуйтесь полем `categories` со списком `id`:

```yaml
categories:
  - getting-started
  - configuration
```

`category` — это просто сахар для списка из одного элемента. На сборке тема
сворачивает оба поля в один нормализованный список `categories`, убирая повторы
по `id`, так что компоненты и микроразметка всегда читают одну форму. Указать
оба поля сразу можно — значение из `category` встанет первым.

**Первая категория — главная.** Именно по ней строятся хлебные крошки и
`BreadcrumbList` в микроразметке. Остальные показываются чипами в подвале поста.

## Разные адреса в разных языках

Категория живёт в каждой локали своей записью, и `slug` у этих записей может
отличаться:

```yaml
# src/ru/_categories.yaml
- id: 'writing'
  name: 'Контент'
  slug: 'kontent'
```

```yaml
# src/en/_categories.yaml
- id: 'writing'
  name: 'Writing'
```

Получаются `/ru/categories/kontent/1` и `/en/categories/writing/1` — каждый
адрес читается на своём языке, что лучше для SEO. При этом переключатель языка
продолжает работать так как категория резолвится по общему `id`.

## Теги

В отличии от категорий тэги задаются прямо в frontmatter поста, без общего реестра.

```yaml
tags:
  - frontmatter
  - разметка # → /ru/tags/razmetka/1
```

Свой слаг задаётся объектной формой:

```yaml
tags:
  - { name: 'Vue.js', slug: 'vue' }
```

Тег в списке тэгов существует ровно до тех пор, пока хотя бы один пост его использует.

::: tip Реестр тегов для CMS
Если вам нужен список тегов для автодополнения в CMS вроде Sveltia, заведите
`_tags.yaml` сами: CMS читает такой файл напрямую, теме он не нужен и она его
не открывает. Храните в нём просто отображаемые имена, а виджет настройте так,
чтобы в пост уходила строка — тогда второго источника истины не появится.
:::

## Настройка

```yaml
# src/site.yaml
themeConfig:
  sidebar:
    tags: true
    categories: true # по умолчанию выключено
    # Сколько тегов показывать в сайдбаре; дальше — ссылка «Все теги».
    # tagsCount: 15 # по умолчанию 15

    # Сколько категорий показывать в сайдбаре; дальше — ссылка «Все категории».
    # categoriesCount: 10 # по умолчанию 10

  # Иконка для ссылок на категории (по умолчанию — tagsIcon).
  categoriesIcon: 'fa6-solid:folder-open'
  postFooter:
    - author
    - donate
    - comments
    - social-share
    - edit-link
    - categories
    - tags
    - similar
```

`postFooter` — это массив строк с именами блоков подвала: `author`, `donate`,
`comments`, `social-share`, `edit-link`, `categories`, `tags`, `similar`.
Порядок ключей задаёт порядок блоков. Массив **полностью заменяет** значение
по умолчанию, поэтому нужно перечислить все блоки, которые вы хотите видеть:
уберите `categories` или `tags`, чтобы скрыть соответствующий блок.

## Ленты и поиск

Теги поста попадают в RSS-ленту как элементы `<category>` со ссылкой на
страницу тега. Категории в ленту не выводятся.
