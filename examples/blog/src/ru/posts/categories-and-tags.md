В теме две таксономии. Они устроены одинаково внутри, но решают разные задачи —
и потому задаются по-разному:

| | Категории | Теги |
| --- | --- | --- |
| Сколько на пост | обычно одна | сколько угодно |
| Смысл | раздел блога | свободные метки |
| Где описаны | `_categories.yaml` | нигде, прямо в посте |
| Хлебные крошки | строятся по ней | нет |
| Страницы | [`categories/`](../categories/) | [`tags/`](../tags/) |
| Блок в подвале поста | `PostCategories` | `PostTags` |
| Фильтр в поиске | `category` | `tag` |

Категорий у блога мало и они образуют его структуру — поэтому они перечисляются
один раз в реестре, а посты ссылаются на них по идентификатору. Тегов бывают
сотни, они возникают по ходу дела — их регистрировать не надо.

## Реестр категорий

Файл `src/<локаль>/_categories.yaml` — единственное место, где категории
описаны. Он устроен так же, как [`_authors.yaml`](authors):

```yaml
# src/ru/_categories.yaml
- id: 'getting-started'
  name: 'Начало работы'

- id: 'configuration'
  name: 'Настройка'

- id: 'writing'
  name: 'Контент'
  slug: 'kontent'
```

У записи три поля, и различать их важно:

| Поле | Что это | Переводится |
| --- | --- | --- |
| `id` | ключ, по которому на категорию ссылаются посты | **нет**, одинаков во всех локалях |
| `name` | видимое название | да |
| `slug` | часть адреса | да, но по умолчанию равен `id` |

Обязателен только `id`. `name` и `slug` без явного значения берутся из него,
так что запись `- id: 'seo'` — уже рабочая категория с адресом
`/ru/categories/seo/1`.

::: tip Можно и в `_site.yaml`
То же самое пишется в `themeConfig.categories` внутри `_site.yaml` — слои
объединяются по `id`. Отдельный файл удобнее: его понимают CMS вроде Sveltia, и
он не раздувает конфиг сайта. Локаль с `extends` наследует реестр родителя и
может переопределить в нём отдельные записи.
:::

## Как задать категорию посту

В посте пишется только `id`:

```yaml
---
title: Запуск блога за 5 минут
category: getting-started
tags:
  - guide
---
```

Ни названия, ни слага в посте нет — они уже описаны в реестре. Если переименовать
рубрику или сменить ей адрес, править придётся одну строку в `_categories.yaml`,
а не каждый пост.

Если посту действительно нужно несколько рубрик — `categories` со списком `id`:

```yaml
categories:
  - getting-started
  - configuration
```

`category` — это просто сахар для списка из одного элемента. На сборке тема
сворачивает оба поля в один нормализованный список `categories`, убирая повторы
по `id`, так что компоненты и микроразметка всегда читают одну форму. Указать
оба поля сразу можно — значение из `category` встанет первым.

**Первая категория — главная.** Именно по ней строятся хлебные крошки и
`BreadcrumbList` в микроразметке. Остальные показываются чипами в подвале поста.

::: warning Только id и только из реестра
Название категории в посте писать нельзя — ни строкой, ни объектом
`{ name, slug }`. Если указанного `id` в реестре нет, тема выводит
предупреждение в консоль сборки и пропускает эту категорию: пост соберётся, но
чипа и хлебных крошек у него не будет.

Это сделано намеренно. Раньше опечатка в названии молча создавала новую рубрику
с одним постом, и заметить это можно было только глазами в списке категорий.
:::

## Разные адреса в разных языках

Категория живёт в каждой локали своей записью, и `slug` у этих записей может
отличаться:

```yaml
# src/ru/_categories.yaml
- id: 'writing'
  name: 'Контент'
  slug: 'kontent'
```

```yaml
# src/en/_categories.yaml
- id: 'writing'
  name: 'Writing'
```

Получаются `/ru/categories/kontent/1` и `/en/categories/writing/1` — каждый
адрес читается на своём языке, что лучше для поиска. Переключатель языка при
этом продолжает работать: страницы категорий — динамические маршруты, файла с
переводом у них нет, поэтому тема сопоставляет их по общему `id`, а не по пути.

Ровно ради этого `id` и отделён от `slug`. Если оставить `slug` по умолчанию,
адрес будет одинаковым во всех локалях — тоже рабочий вариант, просто менее
дружелюбный к читателю.

Ссылка на другой язык не появится, если в целевой локали нет ни одного поста в
этой категории: маршрут для неё не строится, и вести туда некуда.

## Теги остаются свободными

Тегам реестр не нужен — они по-прежнему задаются строкой прямо в посте, а слаг
получается транслитерацией:

```yaml
tags:
  - frontmatter
  - разметка # → /ru/tags/razmetka/1
```

Свой слаг задаётся объектной формой:

```yaml
tags:
  - { name: 'Vue.js', slug: 'vue' }
```

Тег существует ровно до тех пор, пока хотя бы один пост его использует.

Реестра у тегов нет и не будет: слаг получается транслитерацией, поэтому
`разметка` → `razmetka`, а его английский аналог `markup` → `markup`. Это два
разных тега, а не один в двух локалях, и связать их можно было бы только введя
для тегов тот же обязательный реестр — то есть превратив их в категории.

Переключатель языка на странице тега поэтому работает по слагу: для латинских
тегов (`seo`, `config`, `frontmatter`) он один и тот же во всех локалях, и
ссылка ведёт куда надо. Если постов с этим тегом в целевой локали нет — ссылки
не будет.

::: tip Реестр тегов для CMS
Если вам нужен список тегов для автодополнения в CMS вроде Sveltia, заведите
`_tags.yaml` сами: CMS читает такой файл напрямую, теме он не нужен и она его
не открывает. Храните в нём просто отображаемые имена, а виджет настройте так,
чтобы в пост уходила строка — тогда второго источника истины не появится.
:::

## Что появляется автоматически

Заводить страницы руками не нужно, они генерируются на сборке:

| Страница | Адрес |
| --- | --- |
| Список всех категорий | [`categories/`](../categories/) |
| Посты категории | `categories/<slug>/<page>` |
| Популярное в категории | `categories/<slug>/popular/<page>` |

Плюс на страницах постов: хлебные крошки над заголовком, блок категорий в
подвале и облако категорий в сайдбаре.

Списки строятся из постов, а не из реестра: категория, объявленная в
`_categories.yaml`, но не использованная ни одним постом, нигде не показывается
и страницы для неё не создаются.

::: tip Категории появились не сразу
Если ваш блог создан из шаблона более ранней версии, скопируйте в него каталог
`src/<локаль>/categories/` из [шаблона](https://github.com/bozonx/vitepress-theme-neptu/tree/main/packages/blog/template/src/en/categories)
— без этих файлов VitePress просто не построит маршруты категорий. И заведите
`_categories.yaml`: без него ни одна категория из постов не разрешится.
:::

## Настройка

```yaml
# src/site.yaml
themeConfig:
  sidebar:
    tags: true
    categories: true # по умолчанию выключено
    # Сколько категорий показывать в сайдбаре; дальше — ссылка «Все категории».
    categoriesCount: 10
  # Иконка для ссылок на категории (по умолчанию — tagsIcon).
  categoriesIcon: 'fa6-solid:folder-open'
  postFooter:
    - categories
    - tags
```

Уберите `categories` из `postFooter`, чтобы скрыть блок категорий в подвале
поста, — порядок ключей в массиве задаёт порядок блоков.

## Хлебные крошки

Крошки выводятся только у постов с категорией: цепочка
«Главная / Категории / <Категория> / <Заголовок>». Без категории иерархии нет,
и строка «Главная / Заголовок» читателю ничего не даёт — поэтому она не
показывается.

Одновременно с видимыми крошками тема добавляет в JSON-LD
`BreadcrumbList` с теми же шагами — см. [Микроразметка JSON-LD](seo-json-ld).

Компонент `NeptuBreadcrumbs` доступен и отдельно, если нужна своя цепочка:

```vue
<script setup>
import { NeptuBreadcrumbs } from 'vitepress-theme-neptu/components'
</script>

<NeptuBreadcrumbs
  :items="[
    { text: 'Главная', href: '/' },
    { text: 'Документация', href: 'pages/docs' },
    { text: 'Текущая страница' },
  ]"
/>
```

Относительные `href` (`pages/docs`) автоматически получают префикс текущей
локали. У последнего элемента `href` не нужен — текущая страница выводится
обычным текстом.

## Поиск

Категории индексируются как фасет `category`, теги — как `tag`. В интерфейсе
поиска ими можно фильтровать выдачу наравне друг с другом; подробности — в
[Поиск Pagefind](search-pagefind).
