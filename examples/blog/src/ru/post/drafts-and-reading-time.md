Две небольшие возможности, которые нужны почти каждому блогу: возможность
писать пост «в стол» и оценка времени чтения в шапке статьи.

## Черновики

Добавьте `draft: true` во frontmatter — и пост исчезнет из всех публичных
поверхностей блога:

```yaml
---
title: Пост, который ещё не готов
date: 2026-08-01T10:00:00Z
authorId: ivan-k
draft: true
---
```

Скрытие не ограничивается списком постов. Одного фильтра в списке было бы мало:
страница всё равно собирается, поэтому черновик выпадает сразу из пяти мест:

| Поверхность | Что происходит |
|-------------|----------------|
| Списки постов | Свежие, популярные, архив, теги, авторы, похожие — везде отсутствует |
| RSS / Atom / JSON | Не попадает в ленты |
| `sitemap.xml` | Не попадает в карту сайта |
| Поиск (Pagefind) | Не индексируется |
| `<head>` | Добавляется `<meta name="robots" content="noindex, nofollow">`, отключаются JSON-LD, hreflang и canonical |

### Страница остаётся доступной по прямой ссылке

Это сделано намеренно: HTML черновика собирается и лежит по своему URL, просто
нигде не перечислен и помечен `noindex`. Так черновик можно посмотреть «как в
проде» и отправить ссылку на вычитку, не публикуя пост.

Если вам нужно, чтобы файл вообще не попадал в сборку, исключите его через
штатный `srcExclude` VitePress:

```ts
// .vitepress/config.ts
export default async () => defineBlogConfig({
  srcExclude: ['**/*.draft.md'],
})
```

### В dev-сервере черновики видны

По умолчанию черновики **видны** в `vitepress dev` и **скрыты** в
`vitepress build`. Так автор видит неготовые посты в общем списке, пока пишет,
и при этом физически не может выложить их случайно.

Порог определяется по `NODE_ENV`. Переопределить можно явно:

```yaml
# src/site.yaml
themeConfig:
  drafts:
    includeDrafts: false  # прятать даже в dev
    showBadge: true       # бейдж «Черновик» рядом с постом (по умолчанию true)
```

`includeDrafts: true` вернёт черновики во все списки и ленты — включая
продакшен-сборку. Используйте это только для внутренних превью-стендов.

### Бейдж

Пока черновик виден, рядом с ним выводится бейдж — в шапке поста и в списке.
Он же остаётся на странице черновика в продакшен-сборке: это единственный
видимый признак того, что статья не опубликована.

Подписи бейджа переводятся через `t.draftLabel` и `t.draftTitle`.

## Время чтения и количество слов

Обе величины считаются на этапе сборки по исходному markdown. Код в блоках,
инлайновый код и сырой HTML из подсчёта исключаются — длинный листинг конфига
пролистывают, а не читают.

Для CJK-письменностей слова не разделяются пробелами, поэтому символы
считаются поштучно и приводятся к «словам» по коэффициенту 2.

### Настройка

```yaml
# src/site.yaml
themeConfig:
  readingTime:
    enabled: true      # по умолчанию true
    wpm: 200           # слов в минуту
    layouts: ['post']  # где показывать бейдж
```

Оценка никогда не бывает нулевой: любой непустой текст — минимум «1 мин».

Отдельная страница может переопределить список макетов:

```yaml
---
title: Длинная служебная страница
layout: page
readingTime: true
---
```

### В списке постов

По умолчанию в карточках списка время чтения не выводится — включается
отдельно:

```yaml
themeConfig:
  postList:
    showReadingTime: true
```

### SEO

Когда время чтения посчитано, в JSON-LD статьи (`BlogPosting`) добавляются два
свойства:

```json
{
  "@type": "BlogPosting",
  "wordCount": 218,
  "timeRequired": "PT1M"
}
```

В разметке бейдж выводится тегом `<time datetime="PT1M">` — та же длительность
в формате ISO 8601, что и в `timeRequired`.

### Свои макеты

В данных поста, которые тема отдаёт в списки (`PostLite`), появились поля
`wordCount`, `readingTime` и `draft`. На странице самого поста те же значения
лежат в `page.wordCount` и `page.readingTime`.

Готовые компоненты можно собрать в свой макет:

```vue
<script setup lang="ts">
import { PostReadingTime, PostDraftBadge } from 'vitepress-theme-neptu/components'
</script>

<template>
  <PostReadingTime />
  <PostDraftBadge />
</template>
```

Подробнее о сборке собственных макетов — в
[Расширенных возможностях](advanced).
