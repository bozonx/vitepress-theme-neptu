Эта статья есть и на **английском**. Нажмите переключатель языка в верхней
панели — он приведёт вас именно к переведённой статье, а не на главную, потому
что версии связаны между собой. Здесь разбираем, как это связывание устроено и
что оно даёт поисковикам. Устройство самих локалей описано в [Локалях и
мультиязычности](locales).

## Два способа сопоставления

Тема ищет переводы страницы в таком порядке:

1. **Поле `translations`** во frontmatter — если оно есть, оно и есть истина.
2. **Тот же относительный путь** статьи, но в других локалях — запасной вариант.

### Явное сопоставление

```yaml
# src/ru/post/i18n-hreflang.md
translations:
  en: "/en/post/i18n-hreflang"
```

```yaml
# src/en/post/i18n-hreflang.md
translations:
  ru: "/ru/post/i18n-hreflang"
```

Связь указывается с обеих сторон: каждая страница объявляет, где лежат её
переводы.

Явно указывать переводы нужно только в случае когда названия статей и/или папки в которой лежат статьи не одинаковы, тоесть не одинаковый slug пути статьи.

```yaml
translations:
  en: /en/post/hello-world
  'pt-BR': /pt-BR/artigos/ola-mundo
```

### Совпадение по пути

Если вы придерживаетесь какого подхода в котором все пути статей одинаковы во всех локалях, включая папки и подпапки, но разное только содержимое статей на разных языках, то нет необходимости указывать поле  `translations` во frontmatter статей. Тепереводы будут определены автоматически:

```text
en/post/article/hello-world.md  ←→  ru/post/article/hello-world.md  ←→  de/post/article/hello-world.md
```

## Что тема делает со связью

Если статья имеет перевод то **Переключатель языка**, который находится в верхней панели содержит ссылки на версии текущей статьи на других языках.

Так же в `<head>` страницы появляются **Теги hreflang** — по одному
`<link rel="alternate">` на каждую найденную версию, включая текущую, плюс
`x-default`. Откройте исходный код этой страницы, они там:

```html
<link rel="alternate" hreflang="ru-RU" href="https://…/ru/post/i18n-hreflang" />
<link rel="alternate" hreflang="en-US" href="https://…/en/post/i18n-hreflang" />
<link rel="alternate" hreflang="x-default" href="https://…/en/post/i18n-hreflang" />
```

Поисковику это говорит: страницы не дубликаты, а версии одного материала для
разных языков — и показывать читателю нужно ту, что соответствует его языку.

Особенности реализации:

- **Значение атрибута `hreflang` — полный `lang` локали** (`ru-RU`, `pt-BR`), тот, что
  задан в её `_site.yaml`, а не имя папки.
- **`x-default` указывает на основную локаль**. Основная локаль определяется
  полем `primaryLocale` в `.vitepress/config.ts`. Если поле не задано,
  используется `en` (если существует), иначе первая локаль по алфавиту.
  Исключение — главные страницы локалей: для них `x-default` ведёт на корневую
  страницу выбора языка.
- **Версия должна существовать на диске.** Тема проверяет файл перед тем, как
  выводить ссылку, поэтому битых hreflang не бывает.
- Если у вас всего один язык в блоге, то hreflang не появялется в `head` так как в этом просто нет необходимости
- Черновики (`draft: true`) исключаются из hreflang автоматически вместе с canonical и JSON-LD — см. [Черновики и время чтения](drafts-video-podcasts).

::: tip
Абсолютные адреса строятся из `siteUrl` — без него теги не появятся, поэтому
задайте его до публикации (см. [обзор SEO](seo-features)).
:::

## Основная локаль

Поле `primaryLocale` задаёт локаль, которая считается основной для сайта.
Она используется для:

- `x-default` в hreflang-тегах (см. выше);
- `title` и `description` корневой страницы выбора языка при `/`.

```ts
// .vitepress/config.ts
const config: BlogUserConfig = {
  // ...
  primaryLocale: 'ru',
}
```

Значение — имя папки локали (`ru`, `en`, `pt-BR`). Если поле не задано,
основной локалью по умолчанию считается `en` (если она существует), иначе —
первая локаль по алфавиту.

## Как выключить

```yaml
# Глобально — src/site.yaml
themeConfig:
  seo:
    hreflang: false
```

```yaml
# Для одной страницы — во frontmatter
seo:
  hreflang: false
```
