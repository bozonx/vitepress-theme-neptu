Блог, который вы [скопировали из шаблона](getting-started), имеет предсказуемую
структуру. Разберём её, чтобы вы знали, какой файл открывать для каждой задачи.

## Карта папок

```text
my-blog/
├─ src/
│  ├─ .vitepress/
│  │  ├─ config.ts        # конфиг VitePress и темы блога 1 уровня, системые настройки
│  │  └─ theme/           # подключение темы и свои стили
│  ├─ site.yaml           # Конфиг блога 2 уровня. Общие настройки для всех локалей
│  ├─ ru/                 # локаль — папка называется как язык
│  │  ├─ _site.yaml       # Конфиг 3 уровня для конкретной локали
│  │  ├─ _authors.yaml    # профили авторов
│  │  ├─ post/            # ваши посты (файлом или папкой на статью)
│  │  ├─ page/            # отдельные страницы (О блоге, Поддержать…)
│  │  └─ index.md         # главная страница локали
│  ├─ public/             # статические файлы (картинки, медиа, favicon)
│  └─ index.md            # корень сайта: страница выбора языка
├─ package.json
└─ README.md
```

## Два вида контента

Тема различает контент по назначению:

- **Посты** живут в `src/<локаль>/post/` — как `.md`-файлы, возможна вложенная структура, см ниже. Это [ваш основной контент](first-post). Посты имеют дату и показываются в списках последних постов, популярных постов и тд, а так же автоматически попадают в RSS, Atom и JSON фиды (если они настроены).
- **Страницы** живут в `src/<локаль>/page/` и помечены `layout: page`. Это
  статические документы для информации, не входящей в основной контент блога. Они отличаются от постов тем что не имеют даты и не попадают в RSS фиды. Страницы предназначены для дополнительной информации о сайте, правовой и информации и подобном.

## Списки

Все списки, такие как свежие, популярные, архив, авторы, теги, категории генерируются автоматически из ваших постов. Папки в вашей локали (например `src/ru/`) `archive/`, `authors/`, `categories/`, `featured/`, `popular/` содержат файлы которые уже настроены для формирования этих страниц со списками, их редактироват не нужно. Но если вы не используете какуюто функциональность, то помимо выключения ее в настройках так же удалите соотвествующие папки: `authors/`, `categories/`, `featured/`, `popular/`.

## Папки локалей обязательны

Весь контент лежит внутри папки локали: `src/ru/`, `src/en/`, `src/pt-BR/`.
Это правило действует и для одноязычного сайта — одна папка локали
совершенно нормальна. В корне `src/` разрешён единственный markdown-файл —
`index.md`, страница выбора языка.

Сборка проверяет это и останавливается с подсказкой, если найдёт статью
прямо в `src/` или локаль `root`: VitePress-локаль `root` темой не
поддерживается, локаль задаётся явно. Подробнее — в разделе
[Локали и мультиязычность](locales).

Имя папки — языковой тег BCP 47: `ru`, `en`, `pt-BR`, `zh-CN`. Тот же тег
записывается в `lang` в `_site.yaml`, а полное название языка — в `label`.
Где брать коды и названия, разобрано в
[Как назвать локаль](locales#как-назвать-локаль).

Корневой `index.md` — не редирект, а обычная страница со списком языков:

```md
---
layout: false
---

<script setup>
import { LocaleSelector } from 'vitepress-theme-neptu/components'
</script>

<LocaleSelector />
```

Заголовок по умолчанию — название сайта из основной локали; заменить его можно
пропсом `title` или ключом `localeSelector.title` во frontmatter. Почему тема
не делает автоматический переход, объясняется в [Локалях и
мультиязычности](locales).

## Вложенные папки внутри post/ и page/

`post/` и `page/` — это, не обязательно плоская структура файлов. Внутри можно строить любую вложенную структуру, URL повторяет расположение файлов:

```text
src/ru/
├─ post/
│  ├─ hello-world.md              → /ru/post/hello-world
│  ├─ my-article/                 → папка, содержащая статью
│  │  ├─ index.md                 → /ru/post/my-article/
│  │  └─ media/cover.jpg
│  └─ 2026/
│     └─ trip/
│        ├─ day-one.md            → /ru/post/2026/trip/day-one
│        └─ day-one-photo.jpg
└─ page/
   ├─ about.md                    → /ru/page/about
   └─ pricing/
      ├─ index.md                 → /ru/page/pricing/
      └─ media/table.svg
```

Два правила, о которых стоит помнить:

- **`index.md` даёт папочный URL.** `post/my-article/index.md` открывается по
  адресу `/ru/post/my-article/`, а не `/ru/post/my-article/index`.
- **Подпапки не создают разделов.** Вложенность — это способ организовать файлы; группировкой контента для читателя занимаются теги, категории и архив по датам, а не путь.

Так же устроены `page/` и любые ваши собственные папки внутри локали.
Служебные папки списков (`recent/`, `archive/`, `tags/`, `authors/`,
`popular/`) трогать по-прежнему не нужно.

## Что вам предстоит редактировать

| Задача | Файл |
| --- | --- |
| Название блога, навигация, футер | `src/<локаль>/_site.yaml` |
| Настройки для всех локалей сразу | `src/site.yaml` |
| `siteUrl`, поиск, build-time пагинация и интеграции с env | `src/.vitepress/config.ts` |
| Ссылка на репозиторий и автоматическая ссылка «редактировать страницу» | `src/site.yaml` |
| Авторы | `src/<локаль>/_authors.yaml` |
| Цветовая схема и стилевой пресет | `src/site.yaml` — [подробнее](color-themes) |
| Свои стили, шрифты, CSS-переменные | `src/.vitepress/theme/styles.css` |
| Картинки и медиа | `src/public/` или рядом с .md — [подробнее](media-asset-placement) |

Три слоя конфигурации (`config.ts` → `site.yaml` → `_site.yaml`) устроены не
случайно — как они сочетаются и какой из них главнее, разбирается в разделе
[Уровни конфигурации](config-layers). А пока — [добавим первый пост](first-post).
