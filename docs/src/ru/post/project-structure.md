Блог, который вы [скопировали из шаблона](getting-started), имеет предсказуемую
структуру. Разберём её, чтобы вы знали, какой файл открывать для каждой задачи.

## Карта папок

```text
my-blog/
├─ src/
│  ├─ .vitepress/
│  │  ├─ config.ts        # конфиг VitePress и темы (код)
│  │  └─ theme/           # подключение темы, цветовая схема, свои стили
│  ├─ site.yaml           # настройки, общие для всех локалей
│  ├─ ru/                 # локаль — папка называется как язык
│  │  ├─ _site.yaml       # настройки этой локали (заголовок, навигация, футер)
│  │  ├─ _authors.yaml    # профили авторов
│  │  ├─ post/            # ваши посты (файлом или папкой на статью)
│  │  ├─ page/            # отдельные страницы (О блоге, Поддержать…)
│  │  └─ index.md         # главная страница локали
│  ├─ public/             # статические файлы (картинки, медиа, favicon)
│  └─ index.md            # корень сайта: редирект на локаль
├─ package.json
└─ README.md
```

## Три вида контента

Тема различает контент по назначению:

- **Посты** живут в `src/<локаль>/post/` — как `.md`-файлы или как папка на
  статью. Обычные записи с датой и автором, они попадают в списки, ленты,
  архив и поиск. Это [ваш основной контент](first-post).
- **Страницы** живут в `src/<локаль>/page/` и помечены `layout: page`. Это
  статические документы вроде «О блоге» — без даты, вне лент и архива.
- **Списки** (свежие, популярные, архив, авторы, теги) тема генерирует
  автоматически из ваших постов. Отдельные папки `recent/`, `archive/` и другие
  трогать не нужно — они собирают страницы за вас.

## Папки локалей обязательны

Весь контент лежит внутри папки локали: `src/ru/`, `src/en/`, `src/pt-BR/`.
Это правило действует и для одноязычного сайта — одна папка локали
совершенно нормальна. В корне `src/` разрешён единственный markdown-файл —
`index.md`, страница выбора языка.

Сборка проверяет это и останавливается с подсказкой, если найдёт статью
прямо в `src/` или локаль `root`. Подробнее — в разделе
[Локали и мультиязычность](locales).

## Вложенные папки внутри post/ и page/

`post/` и `page/` — это не плоские списки. Внутри можно строить любую
структуру, URL повторяет расположение файлов:

```text
src/ru/
├─ post/
│  ├─ hello-world.md              → /ru/post/hello-world
│  ├─ my-article/                 → папка на статью
│  │  ├─ index.md                 → /ru/post/my-article/
│  │  └─ media/cover.jpg
│  └─ 2026/
│     └─ trip/
│        ├─ day-one.md            → /ru/post/2026/trip/day-one
│        └─ day-one-photo.jpg
└─ page/
   ├─ about.md                    → /ru/page/about
   └─ pricing/
      ├─ index.md                 → /ru/page/pricing/
      └─ media/table.svg
```

Работает всё то же, что и для плоских файлов: посты из подпапок попадают в
свежие, популярные, архив, теги, авторов, RSS, sitemap и поиск.

Два правила, о которых стоит помнить:

- **`index.md` даёт папочный URL.** `post/my-article/index.md` открывается по
  адресу `/ru/post/my-article/`, а не `/ru/post/my-article/index`.
- **Подпапки не создают разделов.** Вложенность — это способ организовать
  файлы; группировкой контента для читателя занимаются теги и архив по датам,
  а не путь.

Так же устроены `page/` и любые ваши собственные папки внутри локали.
Служебные папки списков (`recent/`, `archive/`, `tags/`, `authors/`,
`popular/`) трогать по-прежнему не нужно.

## Что вам предстоит редактировать

| Задача | Файл |
| --- | --- |
| Название блога, навигация, футер | `src/<локаль>/_site.yaml` |
| Настройки для всех локалей сразу | `src/site.yaml` |
| `siteUrl`, поиск, build-time пагинация и интеграции с env | `src/.vitepress/config.ts` |
| Ссылка на репозиторий и автоматическая ссылка «редактировать страницу» | `src/site.yaml` |
| Авторы | `src/<локаль>/_authors.yaml` |
| Цветовая схема и свои стили | `src/.vitepress/theme/` |
| Картинки и медиа | `src/public/` или рядом с .md — [подробнее](media-asset-placement) |

Три слоя конфигурации (`config.ts` → `site.yaml` → `_site.yaml`) устроены не
случайно — как они сочетаются и какой из них главнее, разбирается в разделе
[Уровни конфигурации](config-layers). А пока — [добавим первый пост](first-post).
