Блог, который вы [скопировали из шаблона](getting-started), имеет стандартизированную
структуру. Разберём её, чтобы вы знали, какой файл открывать для каждой задачи.

## Структура пользовательских файлов

Эта структура файлов которую вы будете редактировать для создания контента и настройки блога. По мимо этих файлов есть еще и служебные файлы, о них ниже.

```text
my-blog/
├─ src/
│  ├─ .vitepress/
│  │  ├─ config.ts        # конфиг 1го уровня, системные настройки
│  │  └─ theme/           # расширения и свои стили
│  ├─ ru/                 # локаль — папка называется как язык
│  │  ├─ _site.yaml       # Конфиг 3го уровня для конкретной локали
│  │  ├─ _authors.yaml    # профили авторов
│  │  ├─ post/            # ваши посты (файлом или папкой на статью)
│  │  ├─ page/            # отдельные страницы (О блоге, Поддержать…)
│  │  └─ index.md         # главная страница локали
│  ├─ public/             # статические файлы (медиа, иконки, robots.txt)
│  ├─ site.yaml           # Конфиг 2го уровня. Общие настройки для всех локалей
```

## Два вида контента

Тема различает контент по назначению:

- **Посты** живут в `src/<локаль>/post/` — как `.md`-файлы. Это [ваш основной контент](first-post). Посты имеют дату и показываются в списках последних постов, популярных постов и тд, а так же автоматически попадают в RSS, Atom и JSON фиды (если они настроены).
- **Страницы** живут в `src/<локаль>/page/` и помечены `layout: page`. Это
  статические документы для информации, не входящей в основной контент блога. Они отличаются от постов тем, что не имеют даты и не попадают в фиды. Страницы предназначены для дополнительной информации о сайте, правовой и информации и подобном.

## Папки локалей

Весь контент лежит внутри папки локали, которая представляет из себя языковой тег BCP 47: `src/ru/`, `src/en/`, `src/pt-BR/`, `src/zh-CN/`. (Где брать коды и названия, разобрано в [Как назвать локаль](locales#как-назвать-локаль)). Это правило действует и для одноязычного сайта. Если вы делаете блог только на одном языке, то так же используйте папку локали, например `src/ru/`.

> VitePress-локаль `root` темой не поддерживается. а в корне `src/` разрешён единственный markdown-файл — `index.md`, он рендерит страницу выбора языка.

## Вложенные папки внутри post/ и page/

`post/` и `page/` — это, не обязательно плоская структура файлов. Внутри можно строить любую вложенную структуру, URL повторяет расположение файлов:

```text
src/ru/
├─ post/
│  ├─ hello-world.md              → /ru/post/hello-world
│  ├─ my-article/                 → папка, содержащая статью
│  │  ├─ index.md                 → /ru/post/my-article/
│  │  └─ media/cover.jpg
│  └─ 2026/
│     └─ trip/
│        ├─ day-one.md            → /ru/post/2026/trip/day-one
│        └─ day-one-photo.jpg
└─ page/
   ├─ about.md                    → /ru/page/about
   └─ pricing/
      ├─ index.md                 → /ru/page/pricing/
      └─ media/table.svg
```

Два правила, о которых стоит помнить:

- **`index.md` даёт папочный URL.** `post/my-article/index.md` открывается по
  адресу `/ru/post/my-article/`, а не `/ru/post/my-article/index`.
- **Подпапки не создают разделов.** Вложенность — это способ организовать файлы; группировкой контента для читателя занимаются теги, категории и архив по датам, а не путь.

## Что вам предстоит редактировать

| Задача | Файл |
| --- | --- |
| Название блога, навигация, футер | `src/<локаль>/_site.yaml` |
| Настройки для всех локалей сразу | `src/site.yaml` |
| `siteUrl`, поиск, build-time пагинация и интеграции с env | `src/.vitepress/config.ts` |
| Ссылка на репозиторий и автоматическая ссылка «редактировать страницу» | `src/site.yaml` |
| Авторы | `src/<локаль>/_authors.yaml` |
| Цветовая схема и стилевой пресет | `src/site.yaml` — [подробнее](color-themes) |
| Свои стили, шрифты, CSS-переменные | `src/.vitepress/theme/styles.css` |
| Картинки и медиа | `src/public/` или рядом с .md — [подробнее](media-asset-placement) |

Три слоя конфигурации (`config.ts` → `site.yaml` → `_site.yaml`) устроены не
случайно — как они сочетаются и какой из них главнее, разбирается в разделе
[Уровни конфигурации](config-layers). А пока — [добавим первый пост](first-post).



- `_authors.yaml` - список авторов, работающих с этой локалью или переопределенные имена авторов, если вы список авторов задавали глобально в `src/site.yaml`
- `_site.yaml` - конфиг конкретной локали



## Специальные файлы и папки

Все списки, такие как свежие, популярные, архив, авторы, теги, категории генерируются автоматически из ваших постов. Папки в вашей локали (например `src/ru/`) `archive/`, `authors/`, `categories/`, `featured/`, `popular/` содержат файлы которые уже настроены для формирования страниц с соответствующими списками, их редактировать не нужно.

Всли вы не используете какую-то вышеперечисленную функциональность, то помимо выключения ее в настройках, так же удалите соотвествующие папки: `authors/`, `categories/`, `featured/`, `popular/`, чтобы они не билдились впустую и не увеличивали время билда.

Так же в папке локали находятся специальные файлы:
- `getAllPosts.ts` - служебный файл, его редактировать не нужно
- `loadPosts.data.ts` - так же служебный файл, его редактировать не нужно

А в самом корне src находится `index.md` который рендерит страницу выбора языка, этот файл так же не подлежит редактирования, но если хотите можете поменять его стил, прописав свои стили в `.vitepress/theme/styles.css`    -`.locale-selector-wrapper`
