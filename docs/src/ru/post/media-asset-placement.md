Тема поддерживает три способа организации изображений и других медиафайлов.
Все три работают и для обложек (frontmatter `cover`), и для изображений в
тексте (markdown `![alt](src)`), и для медиа-компонентов. Выберите тот,
который подходит вашему рабочему процессу — их можно свободно смешивать.

## 1. Общая папка public

Классический подход VitePress. Все медиа лежат в `src/public/` и
указываются абсолютным путём от корня public.

```text
src/
├─ public/
│  └─ img/
│     ├─ cover.jpg
│     └─ screenshot.png
└─ ru/
   └─ post/
      └─ my-article.md
```

```yaml
# frontmatter
cover: /img/cover.jpg
```

```md
<!-- тело статьи -->
![Скриншот](/img/screenshot.png)
```

**Когда использовать**: небольшие блоги с малым количеством изображений,
общие ассеты для нескольких постов (логотипы, иконки) или когда удобнее
держать всю медиа в одной папке.

## 2. Рядом с markdown-файлом

Изображения лежат рядом с `.md`-файлом и указываются относительным путём.
Тема автоматически определяет размеры при сборке.

```text
src/
└─ ru/
   └─ post/
      ├─ my-article.md
      ├─ cover.jpg
      └─ screenshot.png
```

```yaml
# frontmatter — относительный путь
cover: ./cover.jpg
```

```md
<!-- тело статьи — относительный путь -->
![Скриншот](./screenshot.png)
```

**Когда использовать**: туториалы со скриншотами, посты, где хочется держать
всё в одном месте. Удаление `.md`-файла удаляет и его изображения.

## 3. Папка на статью с подпапкой media

Каждая статья получает свою директорию. Markdown-файл называется `index.md`,
а медиа лежат в подпапке (обычно `media`). URL остаётся чистым:
`/ru/post/my-article/`.

```text
src/
└─ ru/
   └─ post/
      └─ my-article/
         ├─ index.md
         └─ media/
            ├─ cover.jpg
            ├─ diagram.svg
            └─ photo.png
```

```yaml
# frontmatter — относительно index.md
cover: ./media/cover.jpg
```

```md
<!-- тело статьи — относительно index.md -->
![Диаграмма](./media/diagram.svg)
![Фото](./media/photo.png)
```

**Когда использовать**: статьи с большим количеством изображений, лонгриды
со множеством скриншотов, когда хочется переносить статью (текст + медиа)
одной папкой.

Одним уровнем вложенность не ограничена — как устроены папки контента,
описано в разделе [Структура проекта](project-structure).

## Сравнение

| Подход | Формат пути | Портативность | Авто-размеры | Подходит для |
|---|---|---|---|---|
| Общая папка public | `/img/foo.png` | Нет | Да | Небольшие блоги, общие ассеты |
| Рядом с .md | `./foo.png` | Да | Да | Туториалы, однофайловые посты |
| Папка на статью | `./media/foo.png` | Да | Да | Медиа-тяжёлые, лонгриды |

Все три подхода получают автоматические `width`/`height` и для обложек, и
для отдельных изображений в тексте (тех, что оборачиваются в `<figure>`).

## Как относительные пути работают при сборке

Знать это не обязательно, но полезно при отладке:

- **Изображения в теле статьи** обрабатывает Vite: файл получает хеш в имени
  (`/assets/cover.a1b2c3.jpg`), мелкие картинки встраиваются как data-URI.
- **Все медиафайлы из дерева контента** дополнительно копируются в сборку с
  сохранением пути: `src/ru/post/my-article/media/cover.jpg` становится
  `/ru/post/my-article/media/cover.jpg`. Благодаря этому относительная ссылка
  в собранном сайте работает так же, как в `dev`.
- **Пути во frontmatter** (`cover`) тема разворачивает в путь от корня сайта.
  Это необходимо, потому что обложка показывается не только на самой
  странице, но и в списках, RSS, `og:image` и JSON-LD — там относительный
  путь считался бы от чужого адреса.

Копируются файлы обычных медиа-расширений: изображения (`png`, `jpg`, `jpeg`,
`gif`, `svg`, `webp`, `avif`, `ico`, `bmp`), видео (`mp4`, `webm`, `ogv`,
`mov`, `m4v`), аудио (`mp3`, `wav`, `ogg`, `oga`, `m4a`, `flac`, `aac`) и
`pdf`. Папка `public/` и служебные папки, начинающиеся с точки, не
затрагиваются.

::: tip Хеширование и кеш
У файлов рядом со статьёй в имени нет хеша — как и у файлов из `public/`.
Если вы заменили картинку, оставив то же имя, посетителю может понадобиться
обновить страницу. Для часто меняющихся изображений добавляйте версию в имя
файла: `diagram-v2.svg`.
:::

## Можно совмещать

Распространённый паттерн: общие ассеты (логотип, favicon, OG-изображение по
умолчанию) — в `src/public/`, медиа конкретных статей — рядом с ними:

```md
![Логотип сайта](/img/logo.svg)
![Шаг 1](./screenshot-1.png)
```

## Медиа-компоненты

Встроенные компоненты темы (`YoutubeVideo`, `VideoFile`, `AudioFile`,
`FileDownload`) работают со всеми тремя подходами. Файл из `public/`
указывается путём от корня сайта:

```md
<VideoFile url="/media/demo.mp4" filename="Демо-видео" />
```

Файл, лежащий рядом со статьёй, — относительным путём:

```md
<VideoFile url="./media/demo.mp4" filename="Демо-видео" />
```

Относительный путь в компоненте браузер считает от адреса страницы, поэтому
он работает на самой странице статьи. Если один и тот же файл нужен на
нескольких страницах, положите его в `public/` и указывайте путём от корня
сайта.

## Что выбрать

Начните с `src/public/` — это проще всего. Когда изображений станет много
или над блогом работает команда, переходите на папку на статью: каждая
статья самодостаточна, её проще ревьюить и переносить. Старые посты менять
при этом не нужно — подходы уживаются.
