Вы пишете посты — а страницы-списки тема строит сама. Разберём, какие списки
доступны, откуда берётся отдельная страница вроде «О блоге» и как настроить главную.

## Автоматические списки

Из ваших постов тема генерирует шесть типов списков. Все они доступны из сайдбара
этого демо:

| Список | Что показывает | Адрес |
| --- | --- | --- |
| **Свежие** | все посты по дате, новые сверху | [`recent/1`](../recent/1) |
| **Популярное** | посты по просмотрам (нужен GA4) | [`popular/1`](../popular/1) |
| **Архив** | по годам, затем по месяцам | [`archive/`](../archive/) |
| **Авторы** | посты каждого автора | [`authors/`](../authors/) |
| **Теги** | посты по каждому тегу | [`tags/`](../tags/) |
| **Категории** | посты по каждой рубрике | [`categories/`](../categories/) |

Создавать эти страницы вручную не нужно — они собираются на сборке. Включать и
выключать секции сайдбара можно в `_site.yaml` (см. [Навигация, сайдбар и
футер](nav-sidebar-footer)):

```yaml
# src/<локаль>/_site.yaml
themeConfig:
  sidebar:
    recent: true
    popular: true   # требует popularPosts.enabled в config.ts
    archive: true
    authors: true
    tags: true
    categories: true  # по умолчанию выключено
```

«Популярное» опирается на данные Google Analytics и включается только когда задан
источник GA4 — подробности в [посте про ленты и SEO](seo-feeds-search).

## Авторы, теги и категории

- **Авторы** берутся из [`_authors.yaml`](../authors/): пост ссылается на автора
  через `authorId`, а тема строит страницу автора и подставляет его данные в футер
  и микроразметку.
- **Теги** берутся прямо из поля `tags` постов. Дополнительно в `_tags.yaml` можно
  задать читаемые названия и описания тегов — но это необязательно.
- **Категории** берутся из поля `category` (или `categories`). Одна категория на
  пост задаёт раздел блога и хлебные крошки. Реестр им не нужен. Подробнее —
  [Категории и теги](categories-and-tags).

## Отдельные страницы

Не всё в блоге — статья. Для постоянных страниц (о блоге, контакты, правила)
создайте файл в `src/<локаль>/page/` с `layout: page`:

```md
---
title: О блоге
layout: page
---

# О блоге

Обычный Markdown. Такая страница не попадёт в ленты, архив и списки —
это просто документ.
```

Ссылаться на неё удобно из навигации, футера или нижних ссылок сайдбара
(`href: 'page/about'`). Живые примеры — [«О блоге»](../page/about) и
[«Ссылки»](../page/links).

## Главная страница

Главная локали — это служебный `src/<локаль>/index.md`:

```md
---
layout: home
---
```

Обычную главную рекомендуется не собирать компонентами вручную. Общая
структура задаётся в `site.yaml`, а локализованный текст hero — в
`<локаль>/_site.yaml`:

```yaml
# site.yaml
themeConfig:
  home:
    appearance: auto # auto | light | dark
    maxWidth: 800
    background: none # none | parallax
    # backgroundImage: /img/home.webp
    sections:
      - { type: featured, enabled: true, limit: 3 }
      - { type: latest, enabled: false }
      - { type: popular, enabled: false }
      - { type: tags, enabled: true, limit: 15 }
      - { type: categories, enabled: true, limit: 10 }
```

```yaml
# ru/_site.yaml
themeConfig:
  home:
    hero:
      title: 'Мой блог'
      description: 'Короткое описание блога'
      # Простой вариант одной картинки:
      image: '/img/logo.webp'
      # Или с alt-текстом:
      # image: { src: '/img/logo.webp', alt: 'Логотип' }
      # Или разные картинки для светлой и тёмной темы:
      # image: { light: '/img/logo-light.webp', dark: '/img/logo-dark.webp', alt: 'Логотип' }
      actions:
        - { text: 'Читать статьи', href: 'recent/1', primary: true }
```

> **Требования к картинке в Hero:**
> - **Размеры:** рекомендуемый размер — **320×320px** (на мобильных устройствах масштабируется до 240×240px). Для Retina-экранов можно подготовить 640×640px.
> - **Формат:** лучший результат дают **WebP, PNG или SVG на прозрачном фоне** (маскоты, 3D-аватары, векторные логотипы). Тема автоматически накладывает мягкую объёмную тень (`drop-shadow`), адаптивную к тёмной и светлой теме.

`appearance: auto` следует выбору читателя и показывает переключатель
светлой/тёмной темы. `light` или `dark` фиксирует оформление только на главной и
скрывает переключатель. В её топ-баре остаются поиск, доступный переключатель
языка, appearance, цветовая тема и стиль; обычные nav/social/donate-ссылки там
не выводятся.

Порядок объектов в `sections` задаёт порядок блоков. Поддерживаются:

- `featured` — статьи с `featured: true`; включён по умолчанию, пустой блок скрывается;
- `latest` — последние статьи; выключен по умолчанию;
- `popular` — популярные по GA4; выключен на главной по умолчанию;
- `tags` — облако тегов; включено по умолчанию;
- `categories` — список категорий; включён по умолчанию.

`limit` ограничивает количество статей или тегов. Если его нет, показывается
одна страница — значение `themeConfig.perPage` из `.vitepress/config.ts`.

Интеграция популярных постов включена в теме по умолчанию. Когда GA4 не вернул
данные, сборка предупреждает об этом, а список получает последние статьи и
заголовок «Последние». Настройте `popularPosts.fallback: hide`, чтобы вместо
fallback скрывать список, либо `popularPosts.enabled: false`, чтобы полностью
отключить функции популярных постов.

Markdown после frontmatter всё ещё отображается между hero и секциями. Для
полностью нестандартной главной также можно использовать экспортируемые
`HomeHero`, `HomeFeaturedPosts`, `HomeLatestPosts`, `HomePopularPosts` и
`HomeTags` либо собственный layout. Подробнее — в разделе [Компоненты](components).
