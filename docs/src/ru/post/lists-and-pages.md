Вы пишете посты — а страницы-списки тема строит сама. Разберём, какие списки
доступны, откуда берётся отдельная страница вроде «О блоге» и как настроить главную.

## Автоматические списки

Из ваших постов тема генерирует семь типов списков. Все они доступны из сайдбара
этого демо:

| Список | Что показывает | Адрес |
| --- | --- | --- |
| **Свежие** | все посты по дате, новые сверху | [`recent/1`](../recent/1) |
| **Избранное** | посты с `featured: true` | [`featured/1`](../featured/1) |
| **Популярное** | посты по просмотрам (нужен GA4) | [`popular/1`](../popular/1) |
| **Архив** | по годам, затем по месяцам | [`archive/`](../archive/) |
| **Авторы** | посты каждого автора | [`authors/`](../authors/) |
| **Теги** | посты по каждому тегу | [`tags/`](../tags/) |
| **Категории** | посты по каждой рубрике | [`categories/`](../categories/) |

Создавать эти страницы вручную не нужно — они собираются на сборке. Какие из них
показывать в сайдбаре, решает `sidebar` (см. [Навигация, сайдбар и
футер](nav-sidebar-footer)):

```yaml
# src/<локаль>/_site.yaml
themeConfig:
  sidebar:
    recent: true
    featured: true
    popular: true     # требует popularPosts.enabled в config.ts
    archive: true
    authors: true
    tags: true
    categories: true  # по умолчанию выключено
```

«Популярное» опирается на данные Google Analytics и работает, только когда задан
источник GA4 — подробности в [посте про ленты и SEO](seo-feeds-search).

Сколько постов помещается на страницу списка, задаёт `perPage` в
`.vitepress/config.ts` — это build-time параметр, в YAML он не работает (см.
[Уровни конфигурации](config-layers)). Сколько номеров страниц показывает
пагинация, задаёт `paginationMaxItems` (по умолчанию 5).

## Избранные посты

`featured: true` во frontmatter добавляет статью в редакционную подборку:

```yaml
---
title: Статья, с которой стоит начать
date: 2026-08-01
featured: true
---
```

Флаг ничего не меняет в порядке свежих постов, архива, лент и похожих
материалов — он только наполняет страницу [`featured/1`](../featured/1),
одноимённую секцию сайдбара и секцию `featured` на главной. Внутри подборки
посты идут от новых к старым.

## Авторы, теги и категории

- **Авторы** берутся из [`_authors.yaml`](../authors/): пост ссылается на автора
  через `authorId`, а тема строит страницу автора и подставляет его данные в футер
  и микроразметку.
- **Теги** берутся прямо из поля `tags` постов; отдельный реестр тегов вести не
  нужно.
- **Категории** берутся из поля `category` (или `categories`). Одна категория на
  пост задаёт раздел блога и хлебные крошки. Реестр им не нужен. Подробнее —
  [Категории и теги](categories-and-tags).

## Отдельные страницы

Не всё в блоге — статья. Для постоянных страниц (о блоге, контакты, правила)
создайте файл в `src/<локаль>/page/` с `layout: page`:

```md
---
title: О блоге
layout: page
---

# О блоге

Обычный Markdown. Такая страница не попадёт в ленты, архив и списки —
это просто документ.
```

Ссылаться на неё удобно из навигации, футера или нижних ссылок сайдбара
(`href: 'page/about'`). Живые примеры — [«О блоге»](../page/about) и
[«Ссылки»](../page/links).

## Главная страница

Главная локали — это служебный `src/<локаль>/index.md`:

```md
---
layout: home
---
```

Обычную главную рекомендуется не собирать компонентами вручную. Общая
структура задаётся в `site.yaml`, а локализованный текст hero — в
`<локаль>/_site.yaml`:

```yaml
# site.yaml
themeConfig:
  home:
    appearance: auto # auto | light | dark
    maxWidth: 800
    background: none # none | parallax
    # backgroundImage: /img/home.webp
    sections:
      - { type: featured, enabled: true, limit: 3 }
      - { type: latest, enabled: false }
      - { type: popular, enabled: false }
      - { type: tags, enabled: true, limit: 15 }
      - { type: categories, enabled: true, limit: 10 }
```

```yaml
# ru/_site.yaml
themeConfig:
  home:
    hero:
      title: 'Мой блог'
      description: 'Короткое описание блога'
      # Простой вариант одной картинки:
      image: '/img/logo.webp'
      # Или с alt-текстом:
      # image: { src: '/img/logo.webp', alt: 'Логотип' }
      # Или разные картинки для светлой и тёмной темы:
      # image: { light: '/img/logo-light.webp', dark: '/img/logo-dark.webp', alt: 'Логотип' }
      actions:
        - { text: 'Читать статьи', href: 'recent/1', primary: true }
```

> **Требования к картинке в Hero:**
> - **Размеры:** рекомендуемый размер — **320×320px** (на мобильных устройствах масштабируется до 240×240px). Для Retina-экранов можно подготовить 640×640px.
> - **Формат:** лучший результат дают **WebP, PNG или SVG на прозрачном фоне** (маскоты, 3D-аватары, векторные логотипы). Тема автоматически накладывает мягкую объёмную тень (`drop-shadow`), адаптивную к тёмной и светлой теме.

`appearance: auto` следует выбору читателя и показывает переключатель
светлой/тёмной темы. `light` или `dark` фиксирует оформление только на главной и
скрывает переключатель. В её топ-баре остаются поиск, доступный переключатель
языка, appearance, цветовая тема и стиль; обычные nav/social/donate-ссылки там
не выводятся.

Порядок объектов в `sections` задаёт порядок блоков. Поддерживаются пять типов:

| Тип | Что выводит | По умолчанию |
| --- | --- | --- |
| `featured` | статьи с `featured: true` | включён |
| `latest` | последние статьи | выключен |
| `popular` | популярные по GA4 | выключен |
| `categories` | список категорий | включён |
| `tags` | облако тегов | включён |

`limit` ограничивает количество статей или тегов. Если его нет, показывается
одна страница — значение `themeConfig.perPage` из `.vitepress/config.ts`.
Пустая секция не рисуется: блок избранного на блоге без `featured`-постов
просто не появится.

Секция `popular` требует включённой интеграции с GA4 — по умолчанию она
выключена. Пока данных нет, список остаётся пустым, а сборка выводит
предупреждение. Как её включить — в статье [Ленты, поиск и
SEO-переключатели](seo-feeds-search).

Markdown после frontmatter выводится между hero и секциями — туда удобно
положить приветственный абзац.

## Лента постов вместо лендинга на главной

Главная с `layout: home` — это лендинг: hero, секции, опциональный
параллакс-фон и **никакого сайдбара**. Если вместо этого нужна обычная лента
постов, замените в `index.md` макет и вставьте тот же компонент, что использует
шаблон `recent/[page].md`:

```md
---
layout: util
---

<script setup>
import { RecentList } from 'vitepress-theme-neptu/components'
</script>

<RecentList :curPage="1" />
```

Для популярных постов подставьте `PopularPostsList` (нужен
`popularPosts.enabled`), для избранных — `FeaturedList`.

Три отличия от страницы-шаблона:

- **`paths.js` не нужен.** `index.md` — статический маршрут, а не динамический
  `[page]`, поэтому `params.page` не задан и список открывает первую страницу.
- **Не копируйте `robots: noindex`.** Шаблоны списков помечают себя `noindex`,
  чтобы страницы пагинации не плодили дубли в выдаче. Главная, наоборот, должна
  индексироваться — блок `head` из шаблона не переносите.
- **Пагинация ведёт в никуда.** Базовый URL страниц считается от текущего
  маршрута, поэтому на `/ru/` ссылки укажут на `/ru/2`, которых не существует.
  Главная в этом режиме работает как первая страница ленты; полную пагинацию
  оставьте на `recent/1` и дайте на неё ссылку в навигации или сайдбаре.

Если и этого мало, соберите главную из [компонентов](components) —
`HomeHero`, `HomeFeaturedPosts`, `HomeLatestPosts`, `HomePopularPosts`,
`HomeCategories`, `HomeTags` — или подключите свой layout.
